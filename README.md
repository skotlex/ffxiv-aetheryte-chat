# Aetheryte Chat

파이널판타지 14 **일본 데이터센터**에서 플레이하는 한국어 사용자를 위한 채팅 번역 Dalamud 플러그인입니다.

- **받기**: 게임 채팅으로 들어온 일본어를 한국어로 번역해 보여 줍니다.
- **보내기**: 한국어로 입력하면 일본어로 번역하고, 뜻을 다시 한국어로 확인한 뒤 게임 채팅으로 보냅니다.
  보내면 입력칸에서 빠져나와 바로 게임을 조작할 수 있고, 게임 화면에서 **Ctrl+Enter** 를 누르면 다시 한국어 입력칸으로 갑니다.
  입력칸에서 한 번 더 누르면 보내지 않고 빠져나옵니다 (단축키는 **설정** 탭에서 바꾸거나 끌 수 있습니다).

> **주의**
> - Square Enix와 관련 없는 비공식 도구입니다.
> - 서드파티 도구는 파이널판타지 14 이용약관상 허용되지 않습니다. 사용에 따른 책임은 사용자에게 있습니다.
> - 번역 도구에 따라 채팅 내용이 외부 서비스로 전송됩니다 — 아래 [개인정보와 사용량](#개인정보와-사용량)을 읽어 주세요.

## 설치

1. 게임 안에서 `/xlsettings` → **실험적 기능(Experimental)** 탭을 엽니다.
2. **사용자 정의 플러그인 저장소(Custom Plugin Repositories)** 에 아래 주소를 넣고 `+` 를 누른 뒤 저장합니다.
   ```
   https://raw.githubusercontent.com/skotlex/ffxiv-aetheryte-chat/main/repo.json
   ```
3. `/xlplugins` 에서 **Aetheryte Chat** 을 찾아 설치합니다.
4. `/achat` 으로 창을 엽니다. 처음에는 **번역 도구** 탭이 열립니다.

## 번역 도구 고르기

**번역 도구** 탭에서 1순위 도구를 고릅니다. 고른 도구의 준비 방법·설정·상태가 같은 탭에 나옵니다.

| 도구 | 필요한 것 | 속도 (한 줄) | 특징 |
| --- | --- | --- | --- |
| **Claude CLI** | Claude 구독 (Pro·Max 등) | 약 2초 | 게임 용어·말투가 가장 자연스럽습니다. 권장 |
| **Codex CLI** | ChatGPT 구독 (Plus·Pro 등) | 약 4~5초 (가끔 15초 이상) | 같은 문구를 다시 받으면 바로 보여 줍니다 |
| **Ollama (로컬)** | GPU (그래픽카드 메모리 8GB 이상이면 중간, 12GB 이상이면 큰 모델). 없으면 CPU로 작은 모델 | 약 1초 (CPU만이면 약 3초) | 무료. 채팅이 PC 밖으로 나가지 않습니다 |
| **Papago (웹)** | 없음 | 1초 안팎 | 무료. 비공식 경로라 막힐 수 있고 게임 용어에 약합니다 |

받은 채팅에 전에 번역한 문장이 그대로 다시 오면(전멸할 때마다 다시 올리는 레이드 공략 매크로 등) 어느 도구든 다시 부르지 않고
앞의 번역을 바로 보여 줍니다. 최근 500문장까지 메모리에만 두고, 도구나 그 설정(모델·용어집 등)을 바꾸면 비웁니다.

한 사람이 같은 채널에 잇달아 올린 줄(파티장의 공략 매크로 등)은 **묶어서 한 번에** 번역합니다. 앞뒤 줄을 문맥으로 써서
짧은 줄도 덜 어색하고, 도구를 한 번만 불러 매크로 중간 줄이 밀려 건너뛰어지지 않습니다.
- 마지막 줄 뒤 0.3초 동안 같은 사람의 줄이 더 없으면 번역을 시작합니다 (그래서 평소 한 줄 대화도 0.3초쯤 늦게 시작합니다).
  한 묶음은 10줄·500자까지입니다.
- 더 긴 매크로는 여러 묶음으로 나눠 동시에 번역합니다 (Claude·Codex 는 두 묶음씩, Ollama 는 아래 동시 처리 수만큼).
  30줄(매크로 두 개)이면 3~4묶음이 되고, 모두 번역하기까지 Claude 약 6초, Ollama(`gemma3:12b`, RTX 4090) 약 8초,
  Codex 약 18초 걸렸습니다 (2026-11-20 실측). 대기열 한도(8묶음) 안이라 건너뛰는 줄은 없습니다.
- 번역을 기다리는 동안 같은 사람의 줄이 더 오면 그 묶음에 더합니다.
- Papago 는 지시문을 넣을 수 없어 묶음 안에서도 줄마다 따로 번역합니다.
- 도구가 줄 수를 맞추지 못했거나 원문(일본어)을 그대로 돌려준 답을 주면 그 묶음을 한 번 더 보내고,
  그래도 안 되면 줄마다 번역합니다.

### 예비 도구 (우선순위)

1순위 도구에 문제가 생기면 **예비 도구**로 자동으로 이어 번역합니다. 번역 도구 탭의 **예비 도구 더하기**로 2순위·3순위…를 더하고,
화살표로 순서를 바꿉니다 (2순위를 위로 올리면 1순위와 자리가 바뀝니다).

- 앞의 도구가 준비되지 않았거나(로그인 안 됨·Ollama 꺼짐 등) 번역에 실패하면(시간 초과·연결 실패·로그인 풀림·Papago 막힘 등)
  같은 줄을 다음 도구로 번역합니다. 받은 채팅과 보내기 모두 같습니다.
- 실패한 도구는 60초 동안 건너뛰고 그 뒤 다시 앞 순위부터 씁니다. 로그인이 풀린 도구는 다시 로그인할 때까지 건너뜁니다.
- 예비 도구로 번역하는 중이면 상태 줄에 `Codex CLI 준비됨 (1순위 Claude CLI: 로그인 안 됨)` 처럼 나오고,
  번역 줄의 `[모델]` 에는 실제로 번역한 도구가 나옵니다. 로그인이 안 된 도구가 있으면 상태 줄의 **로그인**으로 로그인합니다.
- 쓰는 도구마다 **준비·설정할 도구**에서 골라 준비해 주세요. 예비로만 둔 Ollama는 미리 GPU에 올리지 않고, 넘어왔을 때 처음 올립니다.
- 뒤에 예비 도구가 있으면 Claude·Codex 는 설정한 제한 시간이 더 길어도 **20초**까지만 기다리고 다음 도구로 넘어갑니다
  (평소 2~5초, Codex 가 늦을 때도 18초 안이었습니다). Ollama 는 처음 모델을 올리는 시간이 길 수 있어 설정한 제한 시간을 그대로 씁니다.

### Claude CLI

1. [Claude Code](https://code.claude.com/docs/en/setup)를 설치합니다. PowerShell에서:
   ```powershell
   irm https://claude.ai/install.ps1 | iex
   ```
   (npm을 쓰신다면 `npm install -g @anthropic-ai/claude-code` 도 됩니다.)
2. 상태 줄의 **로그인**을 누르면 새 창과 브라우저가 열립니다. 구독 계정으로 로그인합니다
   (PowerShell에서 `claude auth login` 을 실행해도 같습니다).
3. 창이 닫히면 자동으로 다시 확인해 `Claude CLI 준비됨` 으로 바뀝니다.

설정: 모델(기본 `haiku` — 빠르고 사용량이 적어 권장), 생각 정도(effort), 제한 시간, 실행 파일 경로.

### Codex CLI

1. [Codex CLI](https://developers.openai.com/codex/cli)를 설치합니다: `npm install -g @openai/codex`
2. 상태 줄의 **로그인**을 누르면 새 창과 브라우저가 열립니다. ChatGPT 계정으로 로그인합니다
   (PowerShell에서 `codex login` 을 실행해도 같습니다).
3. 창이 닫히면 자동으로 다시 확인해 `Codex CLI 준비됨` 으로 바뀝니다.

설정: 모델(비우면 Codex 기본), 생각 정도(reasoning effort, 기본 `low`), 제한 시간, 실행 파일 경로.

**경량 번역**은 기본으로 켜져 있습니다. Codex 의 코딩용 지침·도구 안내를 번역 지침으로 바꿔 한 줄에 쓰는 입력을
약 1만4천 토큰에서 2천8백 토큰으로 줄입니다. Codex CLI **0.154.0 이상**에서 쓰고, 그보다 이전 CLI면 자동으로 기존 방식으로
번역합니다(번역 도구 탭에 이유가 나옵니다). 개인 `config.toml`을 읽지 않으므로 그 안의 모델 설정은 적용되지 않습니다.
로그인은 그대로 쓰며, 원하는 모델은 플러그인의 모델 칸에 지정하세요. 개인 설정이 꼭 필요하면 경량 번역을 끕니다.

성공한 번역은 최근 256개까지 메모리에 보관해, 같은 문구(같은 방향·용어집·모델·설정)는 Codex 를 다시 부르지 않고 바로 보여 줍니다.
번역 도구를 다시 만들거나 플러그인을 끄면 비워집니다.

2026-11-19 실측 (Codex CLI 0.154.0, `gpt-6-astra`, `low`, 채팅 7문장 × 3회씩, 순서를 섞어 번갈아 실행):

| 방식 | 입력 토큰 | 중앙값 | 10초 넘게 걸린 호출 | 그 호출을 뺀 평균 |
| --- | --- | --- | --- | --- |
| 기존 | 13,881~16,834 | 5.1초 | 21번 중 6번 | 4.9초 |
| 경량 | 2,819~2,837 | 4.7초 | 21번 중 6번 | 4.6초 |
| 같은 문구 다시 | 0 | 0.0초 | — | — |

입력 토큰은 약 80% 줄지만 속도는 조금만 빨라집니다. 가끔 11~18초로 늦어지는 호출은 두 방식에서 같은 빈도로 나와
입력 길이가 아니라 서버 쪽 대기로 보입니다. 번역 결과는 거의 같았습니다(띄어쓰기·존댓말 정도 차이).

같은 모델로 기존 방식과 비교하려면 콘솔에 `--codex-standard`를 붙입니다:

```powershell
dotnet run --project tools/TranslatorConsole -- ja2ko --engine codex --model gpt-6-astra "零式4層、初見です。よろしくお願いします！"
dotnet run --project tools/TranslatorConsole -- ja2ko --engine codex --model gpt-6-astra --codex-standard "零式4層、初見です。よろしくお願いします！"
```

### Ollama (로컬)

1. 번역 도구 탭에서 **Ollama 설치**를 누릅니다. 공식 GitHub 릴리스(약 1.6GB)를 받아 검증(SHA-256)한 뒤 플러그인 폴더에 둡니다.
   설치 프로그램·환영 화면·작업 표시줄 아이콘 없이 설치되고, 취소해도 받은 부분은 남아 다시 누르면 이어서 받습니다.
   (이미 [공식 설치 프로그램](https://ollama.com/download)으로 깐 Ollama가 있으면 그것을 씁니다.)
2. 모델을 고르고 **지금 받기**를 누릅니다. 처음에는 이 PC의 그래픽카드에 맞는 모델이 골라져 있습니다
   (목록에 `(이 PC 권장)` 으로 표시). 받기 전에 내려받을 크기와 디스크 여유를 보여 주고,
   받는 동안 진행 막대가 나옵니다. 취소해도 받은 부분은 남아 다시 받으면 이어서 받습니다.
   (PowerShell에서 `ollama pull gemma3:4b` 처럼 받아도 됩니다.)
3. 받은 뒤 상태가 `Ollama (gemma3:4b) 준비됨` 처럼 바뀝니다.

**켜고 끄기는 플러그인이 합니다.** 번역할 때 Ollama가 꺼져 있으면 창 없이 켜고, 플러그인이나 게임을 끄면 같이 끕니다
(게임이 비정상 종료돼도 Windows가 같이 끕니다). 직접 켜 둔 Ollama 앱이 있으면 그것을 그대로 쓰고 건드리지 않습니다.

- 공식 설치 프로그램으로 깔았다면 Windows를 켤 때마다 Ollama 앱이 작업 표시줄에 뜹니다. 번역 도구 탭의
  **Windows를 켤 때 Ollama 앱도 켜기**를 끄면 앱이 뜨지 않고(지금 켜진 앱도 닫음), 그 뒤로는 플러그인이 창 없이 켜고 끕니다.
- 플러그인이 설치한 Ollama는 번역 도구 탭에서 **업데이트 확인**·**지우기**를 할 수 있습니다. 지워도 받아 둔 모델은 남습니다.

설정: 주소(다른 PC의 Ollama도 쓸 수 있습니다), 모델(받아 둔 모델·권장 모델 목록에서 고르기), 미리 GPU에 올려 두기,
모델 유지 시간(keep_alive), 제한 시간.

**모델 고르기**

| 모델 | 받을 크기 | 쓰는 메모리 | 이런 PC에 | 속도 (한 줄) |
| --- | --- | --- | --- | --- |
| `gemma3:12b` | 약 8.2GB | 약 8.6GB | NVIDIA·AMD 외장 그래픽카드 메모리가 12GB 이상인 PC | 약 1초 (RTX 4090), CPU만이면 약 8초 |
| `aya-expanse:8b` | 약 5.1GB | 약 5.7GB | 그래픽카드 메모리가 8GB 이상 12GB 미만인 PC | 약 1초 (RTX 4090), CPU만이면 약 3초 |
| `gemma3:4b` | 약 3.4GB | 약 3.1GB | 그 밖의 PC (내장 그래픽, Intel, 메모리 8GB 미만) | 약 3초, 처음 올릴 때 약 17초 (내장 그래픽 노트북, CPU만) |

- 처음 고르는 모델은 이 표대로 정합니다. 그래픽카드 메모리는 Windows 레지스트리에서 읽고, 게임도 그래픽카드 메모리를
  쓰므로 여유를 두고 권합니다. 다른 PC의 Ollama를 쓰면 이 PC 기준 권장은 보이지 않습니다.
- `aya-expanse:8b` 는 4b와 12b 사이 모델입니다. 시험 문장 22개에서 게임 용어는 12b와 비슷하게 맞았고(`零式4層` 등),
  4b보다 자연스러웠습니다. **비상업 라이선스(CC-BY-NC 4.0)** 라 개인 용도로만 쓸 수 있습니다.
  8GB 카드에서는 게임과 같이 쓰면 일부가 CPU로 돌 수 있습니다 — 그러면 GPU 상태에 빨간 글씨가 나오니 `gemma3:4b` 로 바꿔 주세요.
- 같은 크기대의 `qwen3:8b`·`qwen2.5:7b` 는 번역에 일본어·중국어가 섞였고, `exaone3.5:7.8b` 는 일본어가 약했습니다.
- 모델 메모리는 채팅 번역에 맞춰 문맥 길이를 2048토큰으로 줄여 씁니다 (그대로 두면 Ollama가 그래픽카드에 맞춰 길게 잡아 메모리를 더 씁니다).
  위 쓰는 메모리와 CPU 속도는 RTX 4090·Ryzen 7 7800X3D 에서 잰 값입니다.
- 플러그인이 Ollama를 켤 때는 요청을 **여러 개 동시에** 처리하게 켭니다 (`OLLAMA_NUM_PARALLEL`). 그래픽카드 메모리가
  '고른 모델의 3개 동시 크기 + 게임 몫 4GB' 이상이면 3개, 그 밖에는 2개입니다 (`gemma3:12b` 는 16GB 카드부터, `aya-expanse:8b` 는 10GB,
  `gemma3:4b` 는 8GB 카드부터 3개. 크기를 모르는 모델은 16GB 카드부터). 카드 메모리는 총량이라 다른 프로그램이 쓰는 양은 모르므로,
  3개로 켰는데 모델이 GPU에 다 올라가지 못하면(일부가 CPU로 돎) 그 모델은 2개로 줄여 서버를 다시 켭니다 (게임을 켜 둔 동안 기억합니다.
  다시 켜는 순간 번역 중이던 줄은 실패로 나올 수 있습니다). 동시에 돌려도 요청 하나의 속도는 거의 그대로라, 공략 매크로처럼 묶음이 여럿이면 함께 끝납니다
  (30줄 = 10줄 묶음 셋: 하나씩이면 약 18초, 2개 동시 약 12초, 3개 동시 약 8초. RTX 4090·`gemma3:12b`).
  대신 문맥이 그 수만큼이라 메모리를 더 씁니다. 위 표는 2개 동시 기준이고, 3개 동시면 `gemma3:12b` 약 9.7GB, `aya-expanse:8b` 약 6.1GB,
  `gemma3:4b` 약 3.5GB입니다. 혼자 오는 번역은 5% 안팎 느려집니다. 직접 켠 Ollama(공식 앱 등)는 그 설정을 그대로 씁니다.
- `gemma3:1b` 처럼 더 작은 모델은 원문을 그대로 돌려주거나 영어로 옮기는 등 번역을 제대로 하지 못했습니다.
- 번역 도구 탭의 **GPU 상태**에서 모델이 GPU에 다 올라갔는지 볼 수 있습니다. 일부가 CPU에서 돌면 몇 배 느려지므로
  빨간 글씨로 알려 줍니다. 레이드처럼 GPU가 빠듯할 때는 **지금 내리기**로 바로 비울 수 있습니다(다음 번역 때 다시 올립니다).
- **미리 GPU에 올려 두기**를 켜 두면(기본) 게임을 켤 때 모델을 올려 첫 번역이 빠릅니다. 끄면 첫 번역 전까지 GPU 메모리를 쓰지 않습니다.

### Papago (웹)

준비할 것이 없습니다. 다만 공식 API가 아니라 papago.naver.com 웹 화면의 주소를 부르므로 Naver가 바꾸거나 막으면 동작하지 않고,
많이 쓰면 잠시 제한됩니다. 용어집을 쓸 수 없어 **보내기(한→일)에는 LLM 도구(Claude·Codex·Ollama)를 권합니다** —
소리만 옮긴 오역은 '다시 한국어로' 확인에도 드러나지 않을 수 있습니다.

## 용어집

LLM 도구(Claude·Codex·Ollama)는 **용어집**으로 게임 용어를 한국 서버 유저들이 쓰는 말로 옮깁니다.
번역할 때 **그 줄에 나온 용어만** 함께 보내므로, 용어가 많아도 번역마다 쓰는 토큰은 거의 늘지 않습니다.
보낼 때(한→일)는 한국어 쪽으로 찾아 거꾸로 씁니다.

용어집은 두 가지를 합쳐 씁니다 (번역 도구 탭 아래쪽).

- **기본 용어**: 플러그인과 함께 배포되며, 업데이트하면 함께 늘어납니다. '기본 용어 쓰기'를 끄면 쓰지 않습니다.
  글섭 일본 데이터센터 유저들이 정리한 용어 글(디시인사이드·인벤·블로그, 출처는 `default-glossary.txt` 머리말)에서
  파티 모집·분배·전투·직업 용어를 골라 넣고, 인벤 웹진의 한국 서비스 공식 이름 대조표(2015)에서 기술·콘텐츠·제작채집·지역·던전
  이름 가운데 소리대로 옮기면 틀리는 것(`ザナラーン → 다날란`, `リテイナー → 집사` 등)을 더해 약 190개입니다. 한 글자 약어(`白`·`赤`)나 흔한 말(`なし`·`まとめ`)처럼
  다른 문장에도 걸리는 것은 뺐습니다. 영문 약어(`MT`·`LB`)는 앞뒤에 다른 영문자가 없을 때만 걸려 플레이어 이름 안에서는 걸리지 않습니다.
- **내 용어**: 직접 적는 용어. 한 줄에 `일본어 → 한국어` 하나씩 적고, 기본 용어와 일본어가 같으면 내 용어가 우선합니다.

```
零式 → 영식
絶 → 절
初見 → 초행 | 처음인데 | 처음이라
```

한국어 쪽에 `|` 로 다른 표현을 더하면 보낼 때(한→일) 그 말도 찾습니다. 위 예에서 받은 채팅의 `初見` 은 '초행'으로 옮기고,
보낼 글의 '처음인데'·'처음이라'는 `初見` 으로 옮깁니다. '처음'처럼 흔한 말 하나만 적으면 '처음 뵙겠습니다'에도 걸리니 피해 주세요.

이전 버전에서 용어집을 고쳤다면, 기본 용어와 똑같은 줄은 빼고 고치거나 덧붙인 줄만 '내 용어'로 옮깁니다.
용어집을 비워 두었다면 '기본 용어 쓰기'가 꺼진 채로 옮깁니다.

## 개인정보와 사용량

- **Claude / Codex / Papago**: 번역할 채팅 내용(받은 대화와 보낼 글)이 각각 Anthropic / OpenAI / Naver 로 전송됩니다.
  보낸 사람의 캐릭터 이름은 보내지 않지만, 대화 안에 적힌 이름은 그대로 전송됩니다.
- **Ollama**: 지정한 주소의 Ollama(기본은 이 PC)에서만 처리합니다.
- **Claude / Codex** 는 구독 사용량을 씁니다. 받은 채팅의 일본어 줄마다 번역하므로 붐비는 채널에서는 사용량이 빠르게 늘 수 있습니다.
  **설정** 탭의 **번역할 채널**에서 필요 없는 채널(외치기·떠들기 등)을 꺼 두면 아낄 수 있습니다.
  같은 문장이 다시 오면 전에 한 번역을 그대로 써서 사용량을 쓰지 않고, 한 사람이 잇달아 올린 줄은 한 번에 번역합니다.
- 이 플러그인은 API 키를 받거나 저장하지 않습니다. Claude·Codex는 PC에 로그인해 둔 CLI를 그대로 실행합니다.

## 문제 해결

| 증상 | 해결 |
| --- | --- |
| `claude.exe를 찾지 못했습니다` / `codex.exe를 찾지 못했습니다` | 설치했는데도 나오면 번역 도구 탭의 **실행 파일** 칸에 경로를 직접 넣습니다. PowerShell에서 `(Get-Command claude).Source` 로 경로를 볼 수 있습니다 (npm으로 설치했다면 `.cmd` 가 아닌 실제 `.exe` 경로가 필요합니다 — 비워 두면 자동으로 찾습니다) |

| `로그인 안 됨` | 옆의 **로그인**을 눌러 로그인합니다. 로그인 전에 받은 최근 대화(8줄까지)는 로그인한 뒤 이어서 번역합니다. 쓰는 도중 로그인이 풀려도 같은 상태로 돌아가니 다시 로그인하면 됩니다 |

| 번역이 자주 `제한 시간` 으로 실패 | 번역 도구 탭에서 제한 시간을 늘립니다. Ollama는 처음 모델을 올릴 때 몇 초 더 걸립니다 |

| 알트탭으로 게임에 돌아오면 채팅이 영어로 바뀜 | Windows 11 의 새 한국어 입력기가 창에 돌아올 때마다 영어로 바꿉니다 (플러그인과 상관없이 생깁니다). 설정 탭의 **게임에 돌아오면 한/영 상태 되돌리기** 를 켜 두면 떠나기 전 상태로 되돌립니다 (기본으로 켜져 있습니다) |

## 개발

필요한 것: .NET 10 SDK, XIVLauncher로 한 번 실행한 Dalamud(또는 `DALAMUD_HOME` 환경 변수에 Dalamud 어셈블리 폴더).

```powershell
dotnet build -c Release
```

`src/AetheryteChat/bin/x64/Release/AetheryteChat/latest.zip` 이 배포 파일입니다. 개발 중에는 `/xlsettings` → 실험적 기능 →
**Dev Plugin Locations** 에 `src/AetheryteChat/bin/x64/Debug/AetheryteChat.dll` 을 넣어 불러올 수 있습니다.

게임 없이 번역 도구를 시험하는 콘솔:

```powershell
dotnet run --project tools/TranslatorConsole -- auth --engine codex
dotnet run --project tools/TranslatorConsole -- ja2ko "零式4層、初見です。よろしくお願いします！"
dotnet run --project tools/TranslatorConsole -- ko2ja --engine ollama --model gemma3:12b
dotnet run --project tools/TranslatorConsole -- ja2ko --batch                       # 빈 줄까지 받은 줄을 한 번에 (공략 매크로처럼)
dotnet run --project tools/TranslatorConsole -- ollama serve                        # Ollama 를 켜 두기 (Enter 로 끔)
dotnet run --project tools/TranslatorConsole -- match ja2ko "零式4層、初見です"        # 번역하지 않고 맞은 용어만
dotnet run --project tools/TranslatorConsole -- ja2ko --glossary my-glossary.txt   # 기본 용어집 대신 이 파일 (--no-glossary: 없이)
```

`--engine ollama` 로 번역할 때 이 PC 의 Ollama 가 꺼져 있으면 콘솔이 창 없이 켜고, 끝날 때 같이 끕니다.
`ollama.exe` 는 게임 속 플러그인이 설치한 것(`%APPDATA%\XIVLauncher\pluginConfigs\AetheryteChat\ollama`) → 공식 설치 → PATH
순서로 찾고, `--ollama-exe` 로 직접 지정할 수도 있습니다. 매번 켜면 모델을 올리느라 첫 번역이 몇 초 늦으니,
여러 번 시험할 때는 다른 창에서 `ollama serve` 로 켜 두세요.

기본 용어집은 `src/AetheryteChat.Translation/default-glossary.txt` 입니다 (플러그인에 리소스로 들어갑니다).

### 표본 기록 (개발용)

기본 용어집을 키우려고 **개발자 본인의 게임 PC 에서만** 켜는 기록입니다. 설정 화면에는 없고, 게임을 끈 상태에서
`%APPDATA%\XIVLauncher\pluginConfigs\AetheryteChat.json` 에 직접 적어야 켜집니다. 값이 없으면 아무것도 기록하지 않습니다.

```jsonc
"SampleLogDirectory": "C:\\...\\FFXIV Aetheryte Chat\\samples"
```

- 그 폴더에 날짜별 `samples-YYYY-MM-DD.jsonl` 로 받은 채팅과 번역(`in`), 보낸 글(`out`)을 남깁니다.
  받은 채팅은 캐시로 바로 보여 준 줄(`"cached": true`)과 채팅이 많아 건너뛴 줄(`"state": "skipped"`)도 남겨,
  같은 매크로가 몇 번 나왔는지와 번역하지 못한 줄의 말까지 볼 수 있습니다.
- 보낸 사람은 남기지 않고, 본문 속 플레이어 이름은 그 세션에서 본 이름(전체 이름, 3글자 이상인 이름·성)을 `<이름>` 으로 가립니다.
  가타카나 애칭(タロさん 등)이나 한글로 옮긴 이름은 가리지 못합니다.
- 다른 플레이어의 대화가 들어 있으므로 **커밋하지 마세요**. 저장소 안에 둘 때는 `samples/` 를 쓰면 `.gitignore` 에 들어 있습니다.

개발 PC 에서는 콘솔로 용어 후보를 뽑고 효과를 잽니다. 결과 파일은 모두 표본 폴더에 씁니다.

```powershell
# 용어 후보(가타카나·한자 2자 이상, 영문 약어) → terms.tsv, 엔진끼리 다른 번역·역번역 차이 → disagreements.tsv
# 표본 폴더의 rejected-terms.txt (한 줄에 말 하나, '#' 뒤는 메모) 에 적은 말은 검토했지만 넣지 않기로 한 것이라 뺍니다
dotnet run --project tools/TranslatorConsole -- samples terms <표본 폴더> [--min-count 3]
# 받은 채팅을 원문별로 모아 횟수·채널·번역·맞은 용어 → lines.tsv (대화 전체를 읽고 용어를 고를 때)
dotnet run --project tools/TranslatorConsole -- samples lines <표본 폴더>
# 용어집 용어가 든 줄을 평가 묶음으로 고정 → evalset.jsonl
dotnet run --project tools/TranslatorConsole -- samples evalset <표본 폴더> [--max 200]
# 용어 적중률·시간·입력 토큰. --glossary <파일> / --no-glossary 로 용어집을 바꾸기 전후를 비교
dotnet run --project tools/TranslatorConsole -- samples eval <표본 폴더>/evalset.jsonl --engine codex
```

용어는 자동으로 넣지 않습니다. `terms.tsv` 를 보고 한국 서버에서 실제로 쓰는 말만 골라 `default-glossary.txt` 에 덧붙입니다
(예문은 커밋하지 않습니다).
